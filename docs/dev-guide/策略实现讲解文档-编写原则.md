# 策略实现讲解文档 · 编写原则

> 一份可复用的 checklist，供给任何新策略写「实现讲解」文档时参照。原则从 [PEAD-01e 实现讲解](./PEAD-01e-实现讲解.md) 的写作手法中提炼，与具体策略无关。
>
> | 文档 | 回答什么 | 什么时候看 |
> |---|---|---|
> | 策略设计 | 赚什么钱？为什么有效？绩效预期？ | 想理解策略原理时 |
> | QMT 落地 spec | 整体架构？数据流？关键决策？ | 想知道工程怎么搭时 |
> | 实现计划 | 每一步具体做什么？怎么测？ | 要动手实现时 |
> | **实现讲解** | **代码为什么这么写？每行在算什么？** | **想读懂代码时** |
> | **本文** | **实现讲解这篇文档本身该怎么写？** | **要写一篇新的实现讲解文档时** |

---

## 总纲

> **以「让读者读懂代码」为唯一目标：先全局后细节、先直觉后代码，真名实数举例、正反对比讲坑，每步给出技术理由，对简化保持诚实，用单测收口。**

---

## 七条原则

### P0 · 定位先行

开篇就交代本文在文档矩阵里的位置，用对比表划清和相邻文档（设计 / spec / 计划）的边界，并声明本文聚焦哪几块「精华」、其余只给思路。讲解的唯一目标是**让读者读懂代码**，不是复述设计、也不是写实现流水账。

### P1 · 先全局后细节

任何零件先放进一张**全景流水线图**里再钻进去讲，章节之间用「下一节拆解流水线的第 X 步」串接，让读者始终知道自己在哪。避免一上来就甩函数代码——读者没有全局观就钻细节，读完只记住几行代码、拼不出全貌。

### P2 · 先直觉后代码

每个核心模块先用一段话建立直觉，再贴代码；代码块带**编号中文注释**，每行说清「在干嘛」。直觉段用**人脑思维过程**描述——还原读者已经在用的思考方式，再说代码把它显式化。避免函数直接贴代码 + 一句「这段计算因子」。

直觉段的形态因模块而异，不必套同一个模板：

- **数学因子类**（如 dReport、SUE）：点透「它衡量的不是 X，而是 Y」，再用数值例子验证
- **流程规则类**（如调仓日）：讲「规则是什么、为什么这么定」
- **组装类**（如主循环）：讲「零件怎么拼、每步对应流水线哪步」
- **工程类**（如下单、DB 读取）：讲「职责是什么、有什么坑」

### P3 · 真名实数举例

用真实股票代码 + 真实日期 + 可手算的数字（如茅台 −6、平安 +36），固定一两只代表性股票贯穿全文，不用 `stock_A` / `date1` 这类占位符。每个要点配**正反对比**——正确算出 −6、错误算出 359，用荒谬结果反衬必要性。

### P4 · 对简化诚实

教学可以简化，但必须标注「这里简化了、真实长这样」，绝不把简化版伪装成 ground truth。简化版与真实版的**逻辑必须等价**，只是组织方式不同。文档落后于代码演进时（如新增了幂等保护、净值记录），诚实说明「核心讲解是早期版，新增机制见 X 文档」。

### P5 · 决策给技术理由

每个非显然选择都回答「为什么选 X 不选 Y」，并落到可验证的约束上（QMT 3.6 装不上 SQLAlchemy、set 查询 O(1)、SQL 过滤会漏掉预约日股票），而不是「最佳实践」这种空话。末尾放一张「关键设计决策回顾表」（决策 / 选了什么 / 为什么）作为全篇索引。

| 决策 | 选了什么 | 为什么 |
|---|---|---|
| 工具函数放纯模块 | 与 QMT 环境解耦 | 开发机能单测，QMT 能 import |
| 防前视集中在因子函数 | 不在 SQL 层做 | 单一入口、可单测覆盖边界 |
| 调仓日预计算成 set | 不每次现算 | O(1) 查询，handlebar 早退 |

### P6 · 三处对齐收口

代码、测试、文档三者对齐。把单元测试当作讲解的一部分贴进来，**数值断言必须和 `tests/` 真实代码一致**（如 `−8`、`−3`），等于告诉读者「不信去跑测试」。数值断言优于弱断言（「是负数」），因为能抓出符号反、漏对齐这类 bug。

```python
# actual=2025-05-10 但调仓日是 4/1，必须用 book=2025-04-25
# (2025-04-25) - 对齐(2024-04-28 → 2025-04-28) = -3
self.assertEqual(result.iloc[0]["dreport"], -3)
```

## 篇幅分配

不追求面面俱到。最精华、最容易翻车的几块逐行讲透，外围模块（采集 / DB / 过滤 / 下单）只用「职责 + 关键点 + 为什么」三段式概览。参考比例：核心因子 ≈ 30%，调仓/报告期 ≈ 25%，主循环 ≈ 15%，外围概览 ≈ 20%，决策回顾 ≈ 10%。避免所有模块同等篇幅，稀释真正的核心。

## 落盘前自检

- [ ] 开篇有文档矩阵定位表？声明了聚焦哪几块？
- [ ] 有全景数据流图？章节串接成认知阶梯？
- [ ] 每个核心模块先建立直觉再贴代码？注释说清每行在干嘛？
- [ ] 用真实股票+真实日期+可手算的数字？有正反对比？
- [ ] 教学简化处都标注了「真实代码长这样」？语义等价？
- [ ] 每个非显然决策给了「为什么选 X 不选 Y」的技术理由？有决策回顾表？
- [ ] 贴的测试断言和 `tests/` 一致？
- [ ] 核心篇幅够厚？外围没过度展开？
