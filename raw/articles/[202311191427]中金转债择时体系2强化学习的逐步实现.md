**择时不止是指标。**
前期报告我们介绍了一些常用的指标，但我们总要面对一些更加现实的问题：1、即便指标到位了，考虑交易费用，现在是否要加\减仓，这一点关乎行情级别；2、现在加了何时离开，或者现在减了何时入场——比起“开启”信号，“关闭”信号可能更加需要严谨对待。实践中投资者常常做对了开头（左侧布局）却未能带着盈利离开市场。

  

**强化学习（RL）更善于解决这样的问题。**
多数模型都需要根据“当下”的误差来不断纠正模型，但投资账户追求长期结果，当下的布局（尤其在左侧的）可能需要在未来才能看到回报。同时，我们也要评估动作本身的代价——至少手续费出现了，或者有时我们为了躲避一个短期的风险可能错过后续更大的机会——这些都是强化学习模型更为擅长的。在此，我们不严格介绍强化学习模型的数学原理，但希望介绍一个适合转债投资者的简单框架。下图为一个简单的强化学习要素图，大致包括：

  

1、智能体（Agent）：根据市场环境做出仓位决策（这里使用0、1），由于择时指标本身是连续变量，一般此处会使用一个神经网络；

  

2、状态（state）：即智能体赖以做出判断的指标，和当前的仓位状态；

  

3、奖励（reward）：每一期获得的回报；

  

4、环境：即市场的现实情况，简单理解为向智能体反馈状态和奖励的集合。

**强化学习的对象：智能体**

  

  

**下面我们先构建Agent。**
其基本功能应该包括根据state评估每一个可行的动作的价值，可以理解为根据指标评估做多或做空的价值，然后选择价值更高的一个动作。此时需要一个简单的网络模型，我们可以用下面的结构。里面包括两个线性层，一个Relu作为激活函数，以及一个dropout来控制过拟合。

  

图表2：基础模型设置情况

  

    
    
    import torch  
    import torch.nn as nn  
    import torch.optim as optim  
    import numpy as np  
      
    class DQN_InOne(nn.Module):  
        def __init__(self, input_size, hidden_size, action_size):  
            super(DQN_InOne, self).__init__()  
      
            self.fc1 = nn.Linear(input_size, hidden_size)  
            self.fc2 = nn.Linear(hidden_size, action_size)  
            self.dropout = nn.Dropout(0.2)  
              
        def forward(self, x):  
            x = torch.relu(self.fc1(x))  
            x = self.dropout(x)  
            x = self.fc2(x)  
            return x

**Agent的初始化即包括这样一个网络的构建及其他参数。**
这里涉及到的一个关键参数为Gamma，即对于未来回报的折扣率——为了避免模型将遥远未来的回报过于看重而忽略当下的风险，强化学习模型通常给予一个0.9左右的折扣率。其他参数容易理解，在此不展开。

  

图表3：基础对象设置情况

  

    
    
    class Agent:  
        def __init__(self, input_size, hidden_size, action_size, lr=0.001, gamma=0.9):  
            self.net = DQN_InOne(input_size, hidden_size, action_size)  
            self.optimizer = optim.Adam(self.net.parameters(), lr=lr)  
            self.gamma = gamma # discount factor  
            self.loss_fn = nn.MSELoss()

资料来源：中金公司研究部

  

**下面需要考虑“选择动作”。**
容易理解的是对于训练好的智能体，让它选择价值最大的动作即可，但在训练时我们还需要它时而“跳出”最佳选择，从而探索其他可能性——因此这里要用到一个参数：epsilon。在函数中这个参数的意义是让智能体以epsilon为概率去随机选择一个行为，而非按照固有网络评估。

  

图表4：对象基础动作设置情况

  

    
    
    def get_action(self, state, action_space, epsilon=0.1):  
            if np.random.random() < epsilon: # exploration  
                return np.random.choice(action_space), True  
            else:   
                with torch.no_grad():  
                    q_values = self.net(state)  
                    return torch.argmax(q_values).item(), False

资料来源：中金公司研究部

  

**Agent的最后是根据奖励及下一步的状态进行学习，从而更新网络。** 这里可以看出目标值是当期奖励 +
下期状态价值的最大值（取最大值的意义在于，下一期时智能体仍会选择多空两种动作中价值最大的那一个）。此外一个细节是，在计算下一期的价值（q_next）时，不必引入梯度，因而关闭了其梯度计算。

  

图表5：对象基础更新设置情况

  

    
    
    def update(self, state, action, reward, next_state):  
            q_values = self.net(state)  
            with torch.no_grad():  
                q_next = self.net(next_state)  
            q_target = reward + self.gamma * torch.max(q_next)  
      
            loss = self.loss_fn(q_values[action], q_target)  
            self.optimizer.zero_grad()  
            loss.backward()  
            self.optimizer.step()

资料来源：中金公司研究部

  

  

至此，智能体已经设计完成。需要说明的是，为了力求简单，我们在此处省去了很多在其他场景下需要加入的设定，例如经验回放机制等。

  

  

**训练循环：关注细节**

  

  

**所谓“环境”事实上主要包括数据（择时指标）和回报（基于价格表现）。** 这里有几处细节需要注意：

  

1、我们用transaction_cost_rate来定义交易费用，但在“探索性”的步骤中，交易动作出自随机概率，为避免高昂的交易成本压制智能体探索策略的可能性，我们设定当交易出自epsilon时，不收取交易费；

  

2、奖励值为：下期回报 - 手续费，之所以不是“当期回报”是因为其并不是当期动作所要承担的结果；

  

3、状态值除了择时指标以外，还要包含前期动作，从而让智能体不仅评估是否要做多，而且要考虑是否值得“改变”。从而更符合交易行为。

  

图表6：训练函数

  

    
    
    def train(agent, dfMat, srsIndex,  
              transaction_cost_rate=0.003,  
              epsilon=0.1, n_epochs=500, gamma=0.9):      
          
        n_steps = len(srsIndex) # 训练数据长度   
        rt = srsIndex.pct_change().fillna(0)  
              
        for epoch in range(n_epochs):   
            previous_action = 1          
            for t in range(n_steps-1):  
                state = torch.FloatTensor(list(dfMat.iloc[t, :]) + [previous_action])  
                action, isEpsilon = agent.get_action(state, action_size, epsilon)  
      
                if isEpsilon or (action != previous_action):  
                    transaction_cost = 0.0  
                else:  
                    transaction_cost = transaction_cost_rate  
                  
                reward = rt[t+1] * action - transaction_cost  
                  
                next_state = torch.FloatTensor(list(dfMat.iloc[t + 1, :]) + [action])  
          
                agent.update(state, action, reward, next_state)  
                previous_action = action  
          
            print(f'Epoch: {epoch}, Total Profit: {holdings - 100.0}')

**应用：需注意可解释性**

  

  

作为示例，我们可以采用前期报告中介绍过的指标，包括百元溢价率、甜点数、情绪值、弱势品种表现和均价，暂不考虑其他更为复杂的指标。这些指标都是一维时间序列，将其装入一个dataframe中，以转债等权指数为参考指数进行训练。以32个神经元、仅仅100次训练为例，在2021至23年我们可能看到下面的结果——
尽管当下看起来效果尚可，我们也需要明确它的能力边界。

它可以做到的是：
躲避明显的劣势时间点，例如2021年末，转债估值高企、市场情绪高涨，“新常态”的说法不绝于耳——结果是当时的位置至今未能突破。再如2022年8月，在市场反弹后估值重回高点，甜点转债数量骤降。同时，它也可以找到一些底部机会，例如在2022年末，以及近期。

  

但它不能做到：
精准的切中高点，例如在2022年8月的那次调整前，它在7月15日就发出空仓建议，实际上会错过后续来到的最好的减仓时点。同时，除了其他误判以外，2022年4月、2022年11月以及近期，这个模型都提早了较长时间提示入场（如上图）。

  

那么改进模型呢？
除非承担更大的过拟合风险。事实上，这是由于我们放入的指标均为估值类的偏左侧指标，对于市场何时进入右侧并无数据支持。因此我们要承认，在这个数据范围内，这样的结果应当很接近强化学习的能力上限。

  

**可解释性可以提高其参考价值。**
即便我们采取了措施控制过拟合，但我们仍应清楚，就市场整体的择时训练而言，数据仍是相对匮乏的。我们需要看到一些“可解释性”来提高它的实用价值，例如：它为什么会作出这样的选择。在这方面，captum可以帮助我们，下面为一个示例。

实际上，基于不同的指数与价格，Agent将会作出不同的训练。对于希望在多个策略中选择一个的投资者，上述框架也可以考虑作为参考。例如在进攻和防御策略中寻找平衡。此外，在个券上可以补足择券策略的“虽然推荐，但不在买点”的缺憾。总之，这类模型与传统的学习模型有较大区别，我们选择了一个简单的实现方式，投资者亦有很大的优化空间，尤其是在构建的过程中涉及很多超参数。
