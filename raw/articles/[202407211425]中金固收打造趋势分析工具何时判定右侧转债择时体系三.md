**此前的策略和模型里，我们给了“估值”过高的权重。**
在《迷雾中的利刃》中，我们也把最基础的框架简化为估值与趋势的匹配。但在此前的报告里，估值占去了更大篇幅，即便是关于股票的指标，主要还是以“左侧”为主。而实践中，右侧的重要性不言而喻。这里我们不打算提出更新的，或者更复杂的模型，但希望说明“怎么用”的问题，以及如何程序化实施的问题。

  

**右侧为何重要，"努力"的范围是什么**

  

  

**如果按照“大趋势”划分，实际上我们并没有经历过太多“段”。**
在《适合转债的技术分析》和《如何快速分辨趋势——Python实现趋势分析及债市中的适应性调整》中，我们都介绍过一些趋势分析的方式，但目标无非是将数据降维：

  

1、繁杂交错的K线简化为或为均线，或为线段；

  

2、对简化后的K线，划分成若干“趋势段”，并尽可能地做到：在上行趋势中做多，在下行趋势中等待。以2023年至今的大盘走势为例，图中的“线段”为第一步的工作，“趋势”为第二步。

**关于程序化划分趋势**

  

  

**但以现在转债投资者、研究员的工作量而言，已经很难逐个手动做出这样的区分，这里我们详细介绍程序化的三个技术环节。**
这部分的目标是快速产出类似上面的图表。

  

1\.
日线转为“线段”：这里不是按照已经实现的涨跌幅是否达到某个标准（例如5%）来计量的，而是按是否出现顶、底形态（常称作“顶分型”、“底分型”）。但非常关键的一步反而是，首先剔除掉存在包含关系的前后K线，这样对于避免后续出现含糊不清的情况有很重要的意义——比如保障了“顶”后一定对应的是“底”，而不是连续出现“顶”。
下面的函数未经算法优化，但在做单个标的趋势分析时效率可以接受。仅注意，这里使用了一个递归机制。

  

图表4：趋势确定函数机制实现代码(1)

  

    
    
    def merge_includes(df):  
        if not len(df):  
            return pd.DataFrame()  
        def is_included(row1, row2):  
            return (row1['LOW'] <= row2['LOW'] and row1['HIGH'] >= row2['HIGH']) or \  
                   (row1['LOW'] >= row2['LOW'] and row1['HIGH'] <= row2['HIGH'])  
      
        merged = []  
        i = 0  
        while i < len(df) - 1:  
            date_i = df.index[i]  
            date_i1 = df.index[i + 1]  
            if is_included(df.loc[date_i], df.loc[date_i1]):  
                if df.loc[date_i, 'CLOSE'] > df.loc[df.index[i - 1], 'CLOSE']:  
                    df.loc[date_i1, 'HIGH'] = max(df.loc[date_i, 'HIGH'], df.loc[date_i1, 'HIGH'])  
                    df.loc[date_i1, 'LOW'] = max(df.loc[date_i, 'LOW'], df.loc[date_i1, 'LOW'])  
                else:  
                    df.loc[date_i1, 'HIGH'] = min(df.loc[date_i, 'HIGH'], df.loc[date_i1, 'HIGH'])  
                    df.loc[date_i1, 'LOW'] = min(df.loc[date_i, 'LOW'], df.loc[date_i1, 'LOW'])  
            else:  
                merged.append(df.loc[date_i])  
            i += 1  
        merged.append(df.iloc[-1])  
        merged_df = pd.DataFrame(merged)  
          
        # 递归处理，直到不存在包含关系  
        if any(is_included(merged_df.iloc[i], merged_df.iloc[i + 1]) for i in range(len(merged_df) - 1)):  
            return merge_includes(merged_df)  
        else:  
            return merged_df

    def identify_patterns(df):  
        high_shift1 = df['HIGH'].shift(1)  
        high_shift_minus1 = df['HIGH'].shift(-1)  
        low_shift1 = df['LOW'].shift(1)  
        low_shift_minus1 = df['LOW'].shift(-1)  
      
        top_conditions = (df['HIGH'] > high_shift1) & (df['HIGH'] > high_shift_minus1)  
        bottom_conditions = (df['LOW'] < low_shift1) & (df['LOW'] < low_shift_minus1)  
      
        top_patterns = df[top_conditions]  
        bottom_patterns = df[bottom_conditions]  
      
        patterns = [(row.Index, row.HIGH, 'top') for row in top_patterns.itertuples()] + \  
                   [(row.Index, row.LOW, 'bottom') for row in bottom_patterns.itertuples()]  
      
        patterns.sort(key=lambda x: x[0])  
          
        patterns = pd.DataFrame(patterns,  
                    columns=['date', 'Price', 'Type']).set_index('date')  
        if len(patterns) >= 2:  
            start_date = df.index[0]  
            start_direct = patterns.iloc[1]['Type']  
            if start_direct == 'Top':  
                start_price = df.iloc[0]['HIGH']  
            else:  
                start_price = df.iloc[0]['LOW']  
            patterns.loc[start_date] = [start_price, start_direct]  
        else:  
            print('数据太少，无顶底分形可以识别')  
            return None  
          
        return patterns.sort_index()

**知行难合一的问题：关键是当下**

  

  

**难点就在于，在尚未被明确划分好的当下时点，我们需要判断，站在未来看，此处更会被归为"逆转"还是"延续"。**
不言自明，如果我们能越快发现趋势的改变，越少错判趋势的改变，就能收到越好的效果。一个朴素的想法是用学习模型来给出概率，而非等待趋势完全明朗再行入场 ——
这方面我们建议越简单越好，下面是一个示例。

  

就我们的尝试而言，只要训练得当，参数有一定意义（例如我们选择了当前位置距离前高、前低的距离，关键均线偏离度，更长期的MACD指标等），就能得到一个尚且合理的结果。这里为节约时间，device默认为GPU，但如果设备没有显卡，也会自动使用CPU。

  

图表8：简易模型：SimpleNN

  

    
    
    class SimpleNN(nn.Module):  
        def __init__(self, input_dim, hidden=12, device='cuda' if torch.cuda.is_available() else 'cpu'):  
            super(SimpleNN, self).__init__()  
            self.device = device  
            self.fc1 = nn.Linear(input_dim, hidden) # 隐藏层  
            self.fc2 = nn.Linear(hidden, 1) # 输出层  
            self.dropout = nn.Dropout(0.2) # Dropout层  
            self.relu = nn.ReLU() # ReLU激活函数  
            self.sigmoid = nn.Sigmoid() # Sigmoid激活函数  
            self.to(self.device) # 将模型移动到指定设备  
      
        def forward(self, x):  
            x = x.to(self.device)  
            x = self.fc1(x)  
            x = self.relu(x)  
            x = self.dropout(x)  
            x = self.fc2(x)  
            x = self.sigmoid(x)  
            return x

**但在低频趋势分析这个领域，要谨慎看待这一结果，甚至这类模型。**
因为实战结果可能相去甚远，例如我们如果以交叉熵作为训练，那么模型就会过于看重0或1，而不对把握住拐点带来的好处有很强的积极性 ——
是的，这个模型完全不"左侧"。同时，这类模型非常惯于采取“惰性”判断，即维持此前走势的判断，不做改变。

  

但就主观使用而言，这类模型仍有不错的提示效果，我们在此译为一些符合经验的判断模式：

  

1\.
一个完整的上行趋势，很少由一个单独的线段组成，常见为3~5段。仅由1段构成的情况不是不存在，但概率很低，且一般也是因为后续段未能创新高（新低），进而被程序划入下一个趋势阶段，或者间隔了较长的假期所致。

  

2.如果在月度MACD为负，甚至线性推断的次月MACD同样为负，模型不易给出很高的判断。即便当下已经处于市场的；尤其是，模型不倾向于认为在这种条件下，上行趋势能延续到5个线段甚至更远。相反亦然，月线强势环境下，下跌不易保持。
结合前段，我们可以比较简易地判别，当前结构是否“完成”，我们此前常说的“当前走势还没有结构”即是指当前趋势可能只出现了一个线段，大概率还没有完成

。

3\.
如果前高的距离过远，很难早期判定趋势改变，此时快速突破重要均线（如20\60），可以让模型对趋势的判断有较大改观。但同样，若长期趋势不佳，模型对突破均线也并不敏感。其他有助于判断的指标包括MACD和布林带。

  

4\.
弱势环境下，如果模型的趋势判断值快速提升，且估值偏低，投资者通过转债介入市场将更具优势。2020年五月末是一个很好的例子，彼时转债由于债市因素压缩估值，股市尚在疫情后的调整企稳阶段。到五月末，估值压缩到位，同时趋势性判断也在快速提升（突破0.5），投资者可以寻得一个很好的介入点。

  

5\. 最后，可能也是最重要的，没有证据的情况下不轻易认为趋势已经改变。

**那么，趋势上看，我们如何看待当下市场？**
在上周《反弹的预算》中我们提示关注中证1000（亦代表偏小盘风格）的60分钟级别改变，但实际本周来看，突破未能延续。上述模型显示，距离判断“右侧”为时尚早，就数据来看，此前下行刚走出一个“线段”，就此停止、切入右侧的概率偏低。
因此，对于转债而言，当下的情况是估值已经充分调整，但整体趋势并不占优，存在左侧特征，但难以短期内兑现涨幅。
