** 如何实现AI交易模拟  **

  

  

** AI大模型真的有能力捕捉交易信号，甚至完成账户管理的任务吗。  **
海外的AI交易比赛受到关注，在国内市场，转债交易灵活，可实现T+0交易。这里，我们根据自己的理解，构建了一个模拟环境（当然使用的是真实的市场价格和数据），以验证AI大模型是否有这样的能力，或者，我们能从中学到什么？

  

** 整体结构设计非常简单。  ** 毕竟我们只是将市场数据、账户交易给到上下文，因而要做的只是：1、回测函数 ——
其实这里和是否是AI交易并无差异，我们甚至可以直接用老框架；2、AI决策类（class），接收数据、记录账户、做出指令。以下为具体步骤（对系统开发不感兴趣的投资者可以跳过这一部分）。

1、AI决策类。初始化中，我们主要设定账户信息，其中TradingConfig可以保存一些参数，例如测算时的初始本金、测算期、本次测算涉及的券，以及AI大模型的API等，计算账户的代码则非常简易。

    classEnhancedAITrader:        def __init__(self, config: TradingConfig):        self.config = config        self.capital = config.initial_capital        self.positions = {}        self.trade_history = []        self.nav_history = []        self.decision_log = []  # 记录所有决策（包括HOLD）                # 初始化OpenAI客户端        self.client = OpenAI(            api_key=config.api_key,            base_url=config.api_base_url        )  
            def calculate_metrics(self, current_prices: dict) -> dict:        """计算账户指标"""        cash = self.capital        position_value = sum(            self.positions.get(code, 0) * current_prices.get(code, 0) * 10            for code in self.positions        )        total_value = cash + position_value        nav = total_value / self.config.initial_capital                return {            'cash': cash,            'position_value': position_value,            'total_value': total_value,            'nav': nav,            'position_count': len(self.positions)        }

2、如何将数据给到上下文？这里主要包括了账户信息，利用上面的metrics计算得到，以及市场摘要。这里我们给入了最近5个交易日（或者分钟，小时，取决于数据的频度）和5个周末的数据点。注意，market_data是一个DataFrame，至少包含code、date、close三个列，其余列为自行选择的指标字段。

    def get_enhanced_market_summary(self,                                    date: str,                                   market_data: pd.DataFrame,                                   current_prices: dict) -> str:        """生成增强版市场摘要"""        metrics = self.calculate_metrics(current_prices)  
            summary = f"""        ════════════════════════════════════════        📅 日期: {date}        💰 资金状况:           - 可用现金: ¥{metrics['cash']:,.2f}           - 持仓市值: ¥{metrics['position_value']:,.2f}             - 总资产: ¥{metrics['total_value']:,.2f}           - 净值: {metrics['nav']:.4f}           - 收益率: {(metrics['nav']-1)*100:+.2f}%  
            📊 持仓明细 (共{metrics['position_count']}只):        """if self.positions:for code, qty in self.positions.items():                price = current_prices.get(code, 0)                value = qty * price * 10                cost = next((t['price'] * t['quantity'] * 10for t in reversed(self.trade_history) if t['bond_code'] == code and t['action'] == 'BUY'), 0)                pnl = ((value - cost) / cost * 100) if cost > 0else0                summary += f"   {code}: {qty}张 @{price:.2f} 市值¥{value:,.0f} 盈亏{pnl:+.1f}%\n"else:            summary += "   (空仓)\n"  
    for code in market_data['code'].unique():            df_data = market_data[market_data['code'] == code].set_index('date').loc[:date]            summary += f""" ### {code} 数据 \n            最近5天数据: \n            {df_data.tail(5).to_markdown()}            """  
                summary += f"""\n\n            周度（每5日一个节点），最近5个数据）:\n            {df_data.iloc[::-5].iloc[::-1].to_markdown()}            """        daily_data = market_data[market_data['date'] == date]        summary += f"""\n\n        ### 今日市场快照:\n        {daily_data.to_markdown()}        """  
    return summary

图表4：调用AI模型决策代码

  

  *   *   *   *   *   *   *   *   *   *   *   *   *   *   *   *   *   *   *   *   *   *   *   *   *   *   *   *   *   *   *   *   *   *   *   *   *   *   *   *   *   *   *   *   *   *   *   * 

    
    
    def ai_make_decision(self, market_summary: str, date: str) -> list:        # 获取近期交易历史作为context    recent_trades = self.trade_history[-5:] iflen(self.trade_history) > 0 else []    trade_context = "\n".join([        f"- {t['date']} {t['action']} {t['bond_code']} {t['quantity']}张@{t['price']:.2f}: {t['reason']}"        for t in recent_trades    ])        prompt = f"""## 市场数据：        {market_summary}        近期交易历史:    {trade_context if trade_context else "(暂无交易记录)"}        交易规则:    1. 每次只能买入或卖出10张的整数倍    2. 不可使用杠杆，不可做空    3. 买入前确保资金充足    4. 只能卖出已持有的转债            5. 你可以一次提交多个交易指令（比如同时买入多个转债，或有买有卖）。        请用JSON数组格式回复决策（只返回JSON，不要其他内容），格式如下:    [        {{            "action": "BUY/SELL/HOLD",            "bond_code": "转债代码或null",            "quantity": 数量,            "reason": "决策理由（简短一句话）"        }},        ......    ]        """        response = self.client.chat.completions.create(        model=self.config.model,        messages=[            {"role": "system", "content": system_prompt},            {"role": "user", "content": prompt}        ],        temperature=0,        max_tokens=1000,        response_format={'type':'json_object'}    )        decision_text = response.choices[0].message.content.strip()        decisions = json.loads(decision_text)        return [(d['action'], d.get('bond_code'), d.get('quantity', 0), d['reason'])    for d in decisions]

最后，需要一个执行交易函数，根据指令改变持仓和现金，并返回是否完成了交易。

  

4、交易回测：这里我们没有引入更多库，避免更多复杂的设置，也是为了更好地保存结果。这里只需要市场数据，模型决策，并据此计算净值即可。

  

图表5：交易回测代码

  *   *   *   *   *   *   *   *   *   *   *   *   *   *   *   *   *   *   *   *   *   *   *   *   *   *   *   *   *   *   *   *   *   * 

    
    
    def run_backtest(trader: EnhancedAITrader,  market_data: pd.DataFrame, config: TradingConfig) -> tuple:    dates = sorted(market_data['date'].unique())        for i, date in enumerate(dates):        daily_data = market_data[market_data['date'] == date]        current_prices = dict(zip(daily_data['code'], daily_data['close']))                # 记录净值        metrics = trader.calculate_metrics(current_prices)        trader.nav_history.append({            'date': date,            'nav': metrics['nav'],            'total_value': metrics['total_value'],            'cash': metrics['cash'],            'position_value': metrics['position_value']        })  
            # 定期决策        if i % config.decision_interval == 0:            market_summary = trader.get_enhanced_market_summary(                date, market_data, current_prices            )            decisions = trader.ai_make_decision(market_summary, date)            time.sleep(5)            # 执行所有交易指令            for action, bond_code, quantity, reason in decisions:                if action != "HOLD" and bond_code:                    price = current_prices.get(bond_code, 0)                    if price > 0:                        trader.execute_trade(                            action, bond_code, quantity, price, date, reason                        )  
        nav_df = pd.DataFrame(trader.nav_history)    trades_df = pd.DataFrame(trader.trade_history)        return nav_df, trades_df

** 效果如何？  **

我们以今年7月1日至10月17日为一个简短的观测期，选择成交额最大的十支券（没有选择全市场因为数量太大容易大幅提高上下文长度，消耗Token数量也大幅提高），初始本金100万元。我们给出几个观察：

** 1、"业绩"不稳定：  **
这是自然的，也是我们对这项实验的主要担忧，大模型归根结底是"语言模型"，并不像传统"量化模型"一样，可以用大量数据进行训练、优化，它们甚至不那么擅长于计算
—— 实验中，我们看到多次都出现了卖出数量大于已持仓数量的情况。（几次试验中，开启深度思考能有所缓解）

下图为开源的Deepseek-V3.1-terminus的交易结果，在我们的回测结果中表现相对较好。但是，样本本身就选择了活跃的品种，这样的回报也并不比一直等权持有更强。

** 因此，下面这个问题已经有了回答：“是否AI大模型已经足够好，以至于我们不必为交易再去训练专业模型” —— 答案自然是否定的。  **

** 2、当然，在仅给出技术指标的情况下，我们也寻找到了一些颇具亮点的交易。  **
例如在对某转债（目前已经完成赎回退市）的交易中，7月1日时由于MACD逐步放大、均线上移，模型买入3070张，为整个测算以来的最大单笔交易。随后的7月22日，看到盈利较大，没有更多理由的情况下，兑现了1000张。在8月4日，RSI指标扩大，兑现500张
——
模型在理由充分的情况下大举买入，而在仅仅因为盈利多或者超买（左侧）的情况下，分批小幅兑现，两次只卖出了不到持仓的一半。最后，在临近到期时，才将这个趋势强劲的品种逐步了结获利。

在一些其他品种中，则出现了不太确定的机会，例如仅仅RSI超卖时，模型则尝试小幅抄底，随后待行情确实好转逐步加仓的情况。

  

** 3、但容易受上下文诱导，是大模型的“通病”。  **
例如我们一旦加入“溢价率”这个指标（考虑到这个指标最好以中文输入，一般的模型难以理解类似"convprem"这样的数据库字段），模型就会非常偏好于低溢价率品种，显然在不加入提示词的情况下，模型不理解价格与溢价率的关系，更不会去计算期权模型，而是受到了"溢价率低"的诱导，给出了这个看似合理的回答。

其他的例子如，如果我们包含了RSI、MACD这些指标，模型也会充分利用这些指标，且并不会对原始价格序列有着特别的理解。也因此出现了几次，在已然亏损的情况下，由于RSI超卖而加仓的情况。当然，我们可以探索提示词，让模型更好地执行。

因此，我们可以理解为，相比于一些高频的量化模型，强调端到端（原始的价格序列 —>
交易信号），利用大模型做交易时，更像是从"结果"（其他模型、算法得到的数字）到“使用结果进行交易”。
显然，如果给予其转债定制模型的结论，例如希腊字母或者我们的学习模型等，再让AI大模型去考虑交易信号，自然结果会更好。

** 4、大模型做“主观题”的潜力：  **
相比于量化因子、统计套利等客观题，AI大模型更适合做“主观题”。如果是因子策略、择时策略，那么当然还是尽可能遵照科学的设计执行交易更好，但现实中我们有更多“主观做决定”的情景，此时AI大模型的做法至少有一定的参考价值
——
毕竟，无论是怎样的交易，我们都可以看到一个执行的逻辑（即上面我们让模型返回的“原因”）。而相比于基于统计验证的传统量化模型，AI大模型做出选择的原因更加显性，更加符合人的思路，因此以下情景不妨考虑：

1）多个策略、信号的混合考虑：  这些信号可能有不同的用法，甚至不同的周期（例如转债择时模型和股市情绪指标），加总到一起不仅数据处理难度大，且容易过拟合；

2）主观上需要结合更多信息：  例如投资者希望考虑一些非定量因素，例如新闻、前瞻看法等；

3）同时考虑非交易、非市场因素。  例如合同限制、入库风控，以及负债端管理等因素。

  

** 5、其他需要注意的问题：  **

1）延迟问题，深度思考模型的思维链时间较长，用在高频交易环境里，可能反应不够及时，而非深度思考模型可能效果弱化；

2）测试过程可能消耗较大Token，投资者需要注意上下文是否过长，或者临时大量调用API造成超限。

  

  

** 风险  **  

语言大模型不适配金融专业领域的风险，模型过拟合风险，个券基本面情况超预期
