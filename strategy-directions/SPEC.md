# 量化方向挖掘 — 分层索引法 (Spec)

> 目标：系统性、完整地挖掘 `quant-wiki` 知识资产（~2800 文件 / 564 篇研报），产出一份**全量**可行量化方向目录，服务于「A 股个人投资者 + QMT 实盘 + 不碰重 ML / 付费库 + 终极目标实盘盈利」。
>
> 方法：分层索引法。用 wiki 自带的三层蒸馏结构（overviews → syntheses → concepts）当索引，**不重复读原文**；每层产物落盘，任意新会话只读产物即可恢复。
>
> 约束：上下文窗口有限 → 每个 layer 是一次可独立 pick up 的工作单元。
>
> 创建：2026-07-01。

---

## 一、设计目标与边界

### 目标
- **充分挖掘**：覆盖 wiki 里全部独立可落地的量化方向，不预设 top-N、不替用户砍方向。
- **人定投入**：产出全量菜单 + 理由，由人（投资者）拿着全量信息决定真正投入哪个。
- **上下文友好**：产物即"压缩后的决策形状记忆"，每层可中断、可恢复、不重读 wiki。
- **服务于实盘**：评估模板硬编码数据约束、QMT 用法、红线检查。

### 不做什么
- 不做回测（那是选中方向之后的执行层；本 spec 只到「落地路径草图」）。
- 不碰趋势交易项目（trend-trading-agents）——它只是「我大概有哪些数据能力」的参考。
- 不替用户决定投入哪几个方向——全量保留，档位只是标注不是淘汰。

### 硬约束（来自投资者）
| 约束 | 说明 |
|---|---|
| 数据 | 以 `DATA_SOURCES.md` 盘点为准。日线 OHLCV、实时快照、基本面、北向/龙虎榜/融资融券、事件、新闻、宏观、大宗均已有。**分钟 K 线可经 QMT 获取但当前未接**。付费专业库不可得。 |
| 算法 | 不碰重度机器学习（深度学习因子挖掘、强化学习端到端策略等）。轻量 ML（如简单打分、规则结合统计）可接受，卡片里标注。 |
| 执行 | QMT 已开通，是实盘交易通道；当前无执行层代码。 |

## 二、三层架构

| 层 | 做什么 | 一次会话的输入 | 产物 |
|---|---|---|---|
| **L0 全景地图** | 把 wiki 压成「全部候选方向」清单，**去重归一化** | 8 个 `overviews/` + `CLAUDE.md` 的 tag 全集 + `DATA_SOURCES.md` | `00-landscape.md` |
| **L1 评估卡**（每方向一张，**全部**） | 对每个方向用统一模板评估，产出可决策卡片 | 该方向的 `synthesis` + 2-3 篇核心 `concept` | `cards/{slug}.md` |
| **L2 全量目录** | 汇总所有卡片 → 按档位分组排序 + 组合建议 | 所有 L1 卡片（**读卡片，不读 wiki**） | `catalog.md` |

### 解决"上下文有限"的核心机制
每层产物是「压缩后的、决策形状的记忆」——一张 L1 卡片替代读 5-10 篇 wiki 原文。
**恢复规则**：新会话第一步读 `INDEX.md` + `catalog.md`(若有)，永不从零重读 wiki。

### L1 的并行性
卡片相互独立——可一次会话做 1-3 张，也可派子 agent 同时跑。`catalog.md` 在卡片未全部完成时即已可用（渐进填充）。

## 三、L0：方向归一化（去重）

### 问题
wiki 有 ~1847 个 concept，大量重叠（残差动量 / 隔夜动量 / 路径动量 / 信息比动量… 都是"动量家族"变体）。L0 **不能产 100 个方向**，要把变体折进**家族**。

### "方向"的定义
`方向 = (策略家族 | 因子家族 | 资产类别 × 方法)` 的一个独立可落地单元。
变体作为该方向卡片内的"变体清单"列出，**不单独立卡**。

### 预期产出
归一化后 **~25-40 个方向**。粗分（L0 阶段会细化和增删）：
- **策略类**：动量/趋势、反转、择时、行业轮动、风格轮动、事件驱动(PEAD/SUE)、打新、套利/配对、均值回归
- **因子类**：估值、成长、盈利质量、低波、特质波动率、分析师预期、北向资金、量价/微观结构、另类数据
- **资产类**：可转债、期权、ETF/指数增强、资产配置(风险平价/BL)
- **保留但标注**：期货/CTA、重 ML 因子挖掘 —— 标 🔴，保留并写理由（为什么不适合）

### L0 每个方向一行
`方向 | 一句话定义 | 涉及 tag | 粗判数据需求 | 适配度初判`

### L0 检查点（用户 gate）
**L0 产出后必须先给用户确认方向清单**（有没有漏、有没有该合并的、有没有多余），再批量进 L1。避免 L1 做无用功。

## 四、L1：评估卡模板

每张卡片固定字段。关键是**逐字段对照 `DATA_SOURCES.md`** + **红线检查**。

| 字段 | 内容 |
|---|---|
| 方向名 / 别名变体（带 wiki 链接） | 归一化 |
| 一句话机制 / 为什么有效 | alpha 来源逻辑 |
| 研报证据 | 在 A 股测过吗？结论？时间窗？ |
| **数据需求（逐字段）** | 每个字段标 ✅现有 / 🟡现有需派生 / 🔵需补但可得(如分钟 K 线走 QMT) / ❌付费不可得 |
| 频率/持仓周期 → QMT 用法 | 盘后批量 / 盘中信号 / 事件触发 |
| **红线检查** | 是否依赖 重ML / 付费库 / 分钟级 → 通过 / 触线(能否降级) / 硬否 |
| 落地难度 | 低/中/高 + 卡点 |
| 组合潜力 | 能和哪些方向叠加 |
| **档位** | 🟢立即可做 / 🟡需补数据或研究 / 🔴不适合我（保留 + 理由） |
| 落地路径草图 | 仅 🟢🟡 填：信号怎么算 → QMT 怎么下 → 怎么验 |

### 档位语义（重要：不等于淘汰）
- 🟢 **立即可做**：数据全有、不触红线、逻辑清楚。
- 🟡 **需补数据或研究**：逻辑好但缺一块（如要接 QMT 分钟 K、或要补一个派生字段），补完即可做。
- 🔴 **不适合我**：依赖重 ML / 付费库 / 不可降级的硬约束。**保留**，写清"为什么不适合"——这样用户拿到的是全量信息 + 自带理由。

## 五、L2：全量目录（catalog.md）

**不做 top-N 筛选**。全部方向保留，按档位分组：

```
# 量化方向全量目录
## 🟢 立即可做 (N 个)
  - 方向 A · 一句话 · 落地难度 · 组合伴侣
  - ...
## 🟡 需补数据/研究 (N 个)
  - 方向 X · 缺什么 · 补的路径
## 🔴 不适合我（保留+理由）(N 个)
  - 方向 Y · 为什么不适合
## 组合建议（可选叠加）
  - 例如：行业轮动 + 事件驱动 + 风险平价仓位
```

每行链回对应 L1 卡片，点进去看详情。

## 六、产物组织与会话恢复

### 目录结构
放在 **quant-wiki 仓库根目录的新文件夹**（不进 `wiki/`，避免触发 lint 脚本；Obsidian 里仍可见可搜索）：

```
quant-wiki/strategy-directions/
├── SPEC.md             ← 本文件（规则说明）
├── README.md           ← 怎么恢复、快速上手
├── INDEX.md            ← 进度追踪：哪些卡片 done/pending（恢复锚点）
├── 00-landscape.md     ← L0 产物
├── cards/
│   ├── momentum.md     ← L1，每方向一文件
│   ├── industry-rotation.md
│   └── ...
└── catalog.md          ← L2 全量目录（最终产出）
```

### 恢复协议（任何新会话第一步）
1. 读 `INDEX.md` → 知全局进度、剩余方向。
2. 读 `catalog.md`（若存在）→ 知已完成卡片的档位汇总。
3. 决定本次做哪 1-N 张 L1 卡，或推进 L2。
4. **永不从零重读 wiki**——只读该方向对应的 synthesis + 2-3 concept。

### 文件命名
方向 slug 用英文短横线（`industry-rotation.md`），便于文件系统稳定和 Obsidian 链接。卡片标题用中文（`# 行业轮动`）。

## 七、执行顺序

1. **【已批准设计】** 写本 SPEC → 提交。
2. 建 `README.md` + `INDEX.md` 骨架。
3. **L0**：读 8 个 overviews + tag 全集 + DATA_SOURCES.md → 产 `00-landscape.md`。
4. **L0 gate**：用户确认方向清单（有无遗漏/多余/该合并）。
5. **L1**：按确认后的清单批量产卡片，每张独立、可并行、做一张更新一次 INDEX。
6. **L2**：全部卡片就绪后产 `catalog.md` 全量目录。
7. **出口**：用户从全量菜单点选真正投入的方向 → 对选中项进入 writing-plans 产出可执行计划（信号实现 → QMT 下单 → 验证）。
