## D1. 为什么用分层索引法（而非标签矩阵/单点深挖）

**决策**：L0 读 8 个 overviews 产全景 → L1 逐方向评估卡 → L2 全量目录。

**理由**：核心矛盾是"上下文窗口有限 × 要充分挖掘 2800 文件"。wiki 自带三层蒸馏结构（overviews → syntheses → concepts），天然适合分层压缩——每层产物落盘，新会话只读产物不重读 wiki。标签矩阵法太粗（漏跨标签方向），单点深挖法牺牲广度。

## D2. 为什么不筛选 top-N，全部 34 方向保留

**决策**：探索阶段不淘汰任何方向，🔴也保留并完整调查。

**理由**：投资者明确"我都感兴趣，不要让我选 top"。探索阶段要的是完整菜单 + 理由，由人拿全量信息决定投入哪个。档位（🟢🟡🔴）是数据现状标注，不是淘汰信号。

## D3. 为什么🔴是"数据现状清单"不是"否决书"

**决策**：🔴卡如实记录三态（现在有✅/没有但补能做🔵🟡/拿不到❌），不写"不适合你"。

**理由**：投资者反馈——"逐笔资金流/Level-2/供应链SAM也要继续保留，不要直接推荐或者不适合，但要完整调查"。原则：补不补的决定权在人，我只如实记录现状和代价，不替人判断"不适合"。

**落地**：
- 档位措辞从"不适合我"改为"暂不可做（缺数据/触约束）"
- high-frequency-l2 卡重写：L2 从"❌拿不到"改为"现在没开权限，QMT 有接口，开权限可取"（见 [QMT数据能力](QMT数据能力.md)）
- catalog 删所有"首选/推荐/便于挑选"措辞

## D4. 数据可得性判定标准 = 获取难度

**决策**：四档（✅现有/🟡现有需派生/🔵需补但可得/❌不可得），判定标准是"获取难度"不是具体数据类型。

**理由**：投资者原话——"类似于分钟K这种难度可以的，专业付费数据库不付费爬取也难或者不公开，这种就没办法"。🔵与❌的分界线 = "能像接QMT那样自己写代码稳定拿到吗？"

## D5. 投资者硬约束

| 约束 | 说明 |
|---|---|
| 数据 | 以 DATA_SOURCES.md（trend-trading-agents 仓库）为准 + QMT 可补 |
| 算法 | 不碰重度 ML（深度学习因子挖掘/RL端到端）。**轻量 ML 可接受**（XGBoost打分/集成/AdaBoost），边界见 [ml-heavy-mining 卡片](../cards/ml-heavy-mining.md) |
| 执行 | QMT 已开通，是实盘通道；当前无执行层代码 |
| 目标 | 实盘赚钱为主，研究服从于实盘可用 |
| 基座 | trend-trading-agents 只是"我有啥数据"的参考，不是开发基座 |
