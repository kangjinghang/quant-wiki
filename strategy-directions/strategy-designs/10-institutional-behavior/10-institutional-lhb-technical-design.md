## 0. 系统架构（三层分离）

```
┌─────────────────────────────────────────────────────────────┐
│  数据层（akshare → 东财，每日盘后增量）                       │
│  ├─ 路径1 主信号：stock_lhb_jgmmtj_em   → 机构净买卖（高效）  │
│  ├─ 路径2 私募追踪：stock_lhb_yyb_detail_em → 4+1营业部       │
│  └─ 路径3 深度下钻：stock_lhb_stock_detail_em → 席位明细(慢)  │
│         ↓ 落盘 parquet 缓存（席位明细调用频繁，必须缓存）      │
├─────────────────────────────────────────────────────────────┤
│  信号层（纯 Python，盘后算）                                  │
│  ├─ 席位识别：不换手机构专用 vs 换手（匿名近似）              │
│  ├─ 买入强度 5 分组 → 取最高组（目标 20日 +8.76%）            │
│  ├─ 私募营业部阈值筛选（≥2亿 / ≥1亿）                        │

├─────────────────────────────────────────────────────────────┤
│  下单层（QMT xtquant.xttrader，次日开盘批量）                 │
│  ├─ 读 order_list.csv → 批量下单                             │
│  ├─ 持仓 20 日窗口管理（事件窗口）                            │
│  └─ 到期卖出 / 新信号接力                                     │
└─────────────────────────────────────────────────────────────┘
```

### 1.1 akshare 龙虎榜接口映射表（源码确认）

| 接口 | 层级 | 核心字段 | 配方A用途 | 调用成本 |
|---|---|---|---|---|
| `stock_lhb_detail_em(start,end)` | 股票×日 汇总 | 代码/上榜日/龙虎榜净买额/买入额/卖出额/上榜后1/2/5/10日 | 拿当日上榜清单 + 总净买额 | 按日期段，1次/段 |

| `stock_lhb_hyyyb_em(start,end)` | 活跃营业部 | 营业部名称/**营业部代码**/买卖总额 | **初始化用**：按名称反查营业部代码 | 按日期段 |

> 💡 **关键决策——主信号走 `jgmmtj` 不走 `stock_detail`**：`jgmmtj` 一次按日期段拉取，直接给出每只股票的"买方机构数/卖方机构数/机构净买额"，正好对应开源用的三个指标（净流入金额、净流入占比、买卖席位数量）。而 `stock_detail` 要逐只逐日×2 次调用（一天50只=100次HTTP），仅用于候选股的深度下钻。

### 1.2 数据路径详解

#### 路径1（主信号·高效）：机构净买卖 — `stock_lhb_jgmmtj_em`

一次按日期段拉取，输出每日每只上榜股的机构聚合数据。

```python
# 伪代码：拉取某日全市场机构买卖
import akshare as ak
df = ak.stock_lhb_jgmmtj_em(start_date="20260702", end_date="20260702")
# 输出列：代码/名称/买方机构数/卖方机构数/机构买入总额/机构卖出总额/
#         机构买入净额/市场总成交额/机构净买额占总成交额比/换手率/流通市值
```

**派生三个信号指标**（对应开源"净流入金额/净流入占比/买卖席位数量"）：
- `net_amt = 机构买入净额`（净流入金额）
- `net_ratio = 机构净买额占总成交额比`（净流入占比）
- `seat_diff = 买方机构数 - 卖方机构数`（买卖席位数量之差）

> ⚠️ **匿名近似（重要）**：`jgmmtj` 给的是**全部"机构专用"席位的聚合**（含换手+不换手）。东财公开数据里"机构专用"是匿名的（多只机构共用同一标签，无法精确识别单机构的换手行为）。开源原文"机构被限日内反向交易"意味着**不换手是常态、换手是例外**，故聚合数据中不换手占主导，近似可接受。若需精确过滤换手，走路径3下钻。

#### 路径2（私募追踪·独立）：4+1 营业部 — `stock_lhb_yyb_detail_em`

追踪开源识别的 4 个量化私募营业部 + 1 个权益私募营业部：

|---|---|---|
| 中国中金财富证券北京宋庄路 | 净流入≥2亿 | 第15交易日 +5.28% |
| 华泰证券股份有限公司总部 | 净流入≥2亿 | （4个协同，同阈值）|
| 中国国际金融上海黄浦区湖滨路 | 净流入≥2亿 | （同上）|
| 招商证券深圳深南东路 | 净流入≥2亿 | （同上）|
| 国信证券深圳振华路（权益私募）| 买入≥1亿 | 20日 +7.55% |

## 2. 信号层设计

### 2.1 席位识别算法（不换手 vs 换手）

**原文逻辑**（开源 2022）：机构被限日内反向交易，龙虎榜应呈单向；出现"又买又卖"的换手机构专用席位反而可疑（多伴随量化私募），故不换手才代表真实机构。

**匿名约束下的近似实现**：东财"机构专用"匿名，无法识别单个机构是否换手。采用**聚合近似**——用 `seat_diff = 买方机构数 - 卖方机构数` 衡量整体买卖不平衡：
- `seat_diff > 0` 且较大 → 买方机构占主导（近似"不换手净买入"群体强）
- `seat_diff ≈ 0` → 买卖机构均衡（换手嫌疑大）

```
算法（伪代码）：
对每只上榜股：
  1. seat_diff = buy_inst_n - sell_inst_n
  2. 若 seat_diff > 0：标记为"净买入倾向"，进入多头候选
  3. 若 seat_diff < 0：标记为"净卖出倾向"，进入规避名单
（这是 jgmmtj 聚合层的近似；精确到单席位需路径3下钻）
```

> 💡 **何时上路径3提纯**：当路径1候选股 >20 只时，对每只下钻 `stock_detail`，算买卖榜"机构专用"席位的重叠度，剔除重叠高（换手多）的。这是把"近似"提纯为"精确不换手"的可选增强。

### 2.2 买入强度 5 分组（主信号）

复现开源"不换手机构专用净流入最高组 20日 +8.76%"。对当日全部上榜股，按三个指标各分5组：

```
算法（伪代码）：
对 trade_date 当日所有上榜股（来自 jgmmtj）：
  1. 按三个指标分别排序，各分5组（Q1最低 ~ Q5最高）：
     - net_amt   （机构净买额）
     - net_ratio （净买额占比）
     - seat_diff （买卖席位数之差）
  2. 多头候选 = 三个指标都在 Q5（最高组）的股票交集
  3. 目标绩效：这个交集组 20日超额 +8.76%（原文）
```

> ⚠️ **口径核对**：开源 +8.76% 是**"不换手机构专用"子样本**的5分组结果；我们用 jgmmtj 全机构聚合做近似，实盘可能略有偏差。回测阶段（§4）首要任务就是**验证这个近似能否复现 +8.76%**，若偏差大再上路径3提纯。

### 2.3 三类多头候选合并

| 候选来源 | 筛选条件 | 目标绩效 | 数据路径 |
|---|---|---|---|
| ① 不换手机构净买入最高组 | 三指标∈Q5 | 20日 +8.76% | 路径1 |
| ② 量化私募营业部净流入 | 4营业部 net_amt ≥ 2亿 | 第15日 +5.28% | 路径2 |
| ③ 国信振华路买入 | buy_amt ≥ 1亿 | 20日 +7.55% | 路径2 |
| ④ 规避名单 | 量化私募净流出≥1亿 | 20日 −5.60% | 路径2（剔除用）|

```python
def generate_candidates(trade_date: date) -> pd.DataFrame:
    """生成当日候选池。返回 schema:
       code/name/signal_type(①②③)/net_amt/entry_date/hold_days(20)"""
    c1 = top_quintile_jgmmtj(trade_date)      # 路径1 Q5交集
    c2 = quant_private_inflow(trade_date, threshold=2e8)  # 路径2 4营业部
    c3 = zhenhua_road_buy(trade_date, threshold=1e8)     # 路径2 国信振华路
    avoid = quant_private_outflow(trade_date, threshold=1e8)  # 规避
    pool = concat([c1, c2, c3]).drop_duplicates(subset='code')
    pool = pool[~pool.code.isin(avoid.code)]  # 剔除规避名单
    return pool
```

## 3. 下单层设计（QMT xtquant）

> ⚠️ **参考级接口**：[QMT数据能力.md](../reference/QMT数据能力.md) 仅覆盖 `xtdata`（行情），未覆盖 `xttrader`（交易）。以下下单接口基于 xtquant 通用交易流程设计，**函数名/参数需对照你的 QMT 版本和券商对接确认**后再实现。

### 3.1 交易流程

```
每日 T+1 开盘前（09:25-09:30）：
1. 读 order_list.csv（信号层 T 日盘后产出）
2. 连接 xttrader：connect → 订阅账户
3. 查当前持仓 → 算调仓 diff（新增/减仓/清仓）
4. 批量下单（市价或开盘价限价）
5. 回填成交结果 → 更新持仓表
```

### 3.2 调仓时点

| 时点 | 动作 |
|---|---|
| T 日 18:00 后 | 信号层跑全流程，产出 order_list.csv |
| T+1 09:25-09:30 | 下单层读 csv，批量挂开盘价限价单 |
| T+1 09:35 | 查未成交，对未成交改市价单或撤单 |

## 5. 回测验证方案（确认"做对了"的标准）

**首要目标**：验证主信号能否复现开源 **20日 +8.76%** 的结论。

```
回测步骤：
1. 用路径1（jgmmtj）拉 2023-01 至今数据
2. 每个交易日：三指标取Q5交集 → 多头候选组
3. 对每只候选股，算"上榜后20交易日相对沪深300累计超额"
4. 全样本取均值，对照 +8.76%
   ├─ 偏差 <2pp：近似可接受，直接上实盘
   ├─ 偏差 2-5pp：上路径3提纯（过滤换手），再测
   └─ 偏差 >5pp：检查指标构造（可能 net_ratio 口径不对）
5. 同时验证②③（+5.28%/+7.55%）作为交叉验证
```

> 💡 **超额收益计算口径**：需用前复权日线（`ak.stock_zh_a_hist` 或 QMT `get_market_data_ex`），基准选**沪深300**（对应组合年化30.9%的口径）。注意路径2营业部的原文基准是 **Wind全A**（与主信号基准不同，见 playbook §二口径提示）。

## 6. 衰减监控与红线
