# 提示词 · Playbook 策略详细实现设计

> **使用方法**：把整份内容复制给 LLM，末尾补一句"对 #0N 方向执行"。LLM 即可按流程把一个 playbook 拆解成多份"策略详细实现"设计文档。
>
> **拆分原则**：以 playbook 配方为主线（配方 A/B/C/D → Phase 1/2/3...），再纳入 playbook 配方之外但有价值的独立机制（§二/§七/§九里的独立 alpha）。LLM 自主完成拆分，**不需要与用户确认拆分方案**。
>
> 已验证可复用：#01 PEAD（定标准，6 份）、#02 行业轮动（9 份）、#05 资金流北向（10 份）。

## 你的角色

你是策略落地设计助手。任务：把一份 strategy playbook（原理+证据+配方）转化为**多份"策略详细实现"文档**——介于 playbook 与代码之间的**策略层中间层**。

**关键定位**：这是**策略说明书**，不是代码技术设计。拿到这份文档，任何人都能照着写出代码，但文档本身**不陷入代码细节**。

**层级关系**：
```
playbook 策略手册（原理 + 证据 + 配方）
        ↓
【本提示词产出】策略详细实现  ← 你写的这一层
  · 因子怎么算（公式 + 每步取什么值，用文字和数学，不写代码）
  · 选股/选行业规则、过滤条件、调仓规则
  · 参数选择依据、绩效对标、失效红线
        ↓
代码技术设计（接口、函数、模块、伪代码）← 不是本层
        ↓
代码实现
```

## 不可破坏的约束

1. **playbook 有错就直接改 playbook**——不要只在设计文档里标注"修正/playbook 未提"。先改 playbook 对齐原文，再让设计文档和修正后的 playbook 一致。
2. **所有数字/参数必须来自 Read 到的原文**，禁止编造。绩效数字必须核对**口径**（多头超额 vs 多空、年化 vs 累计、胜率定义）。
3. **引用原文必须带链接**——用 playbook 同款的相对路径格式 `📖 [机构 年.月](../../raw/articles/[时间戳]文件名.md)`，可点击跳转。
4. **设计文档不写与 playbook 的对比语言**——不写"修正/补全/playbook 未提/与 playbook 一致"。文档假设 playbook 就是对的，直接陈述策略。
5. **完整复现优先，缺数据标注+预留接口**——不降级、不省略。数据缺口写"三档实现路径"（立即可用 / 数据升级后 / 付费源），起步走档 1 但完整版接口预留。
6. **接口名进附录**，不进主体。主体只写字段级需求。

## 执行流程（7 步）

### 步骤 1：架构拆分（自主决策，不询问用户）

**拆分原则（固定，无需与用户确认）**：
- **以 playbook 配方为主线**——配方 A/B/C/D... 每个配方对应一份设计文档，按 playbook 的递进顺序排 Phase
- **再纳入 playbook 配方之外但有价值的独立策略**——通读 §二证据表、§七组合潜力、§九附录，把有独立 alpha、有完整原文佐证、可独立运行的机制也写成设计文档（命名为 `0Nx/y/z`）
- 共享层（数据/工具/前视防护/下单层）单独成文（`0N-shared`）

**操作**：
1. Read **源 playbook 全文**，列出：
   - 配方清单（A/B/C/D...）→ 核心 Phase 1/2/3...
   - 配方之外的有价值独立机制清单 → 附加 Phase x/y/z
2. 参考下方【文档拆分原则】和【已验证示例】决定每份定位
3. **自主完成拆分，直接进入步骤 2**——不要用 AskUserQuestion 问用户"拆几份/是否纳入附加"，按上述原则自己定

**只在以下情况才用 AskUserQuestion 问用户**：
- playbook 本身结构不清，无法判断配方递进关系
- 某个附加机制"是否有价值"存在边界模糊（如某研报机制陈旧、绩效不明）
- 用户主动要求优先做某一份

### 步骤 2：原文核实（每份设计文档都要做）

**禁止仅凭 playbook 写设计文档**——playbook 是二手总结，可能有简化/错误。每份设计文档动笔前必须 Read 对应的原始研报，核对：
- 因子构造的精确公式（playbook 常简化）
- 关键参数的具体值与最优性证据（playbook 常只给一个值，不给"为什么"）
- 绩效数字的口径与回测期
- 失效边界/红线

**并行提效**：多份设计文档的原文核实可派多个 general-purpose agent 并行做（一条消息里多个 Agent 工具调用）。每个 agent 的 prompt 必须包含：
1. 原文**绝对路径**
2. 要提取的**编号问题清单**（具体到因子定义/参数/绩效口径）
3. 要求"按编号列出，每条带原文引述（> 引用块）和所在章节；找不到明确说'原文未提及'"

### 步骤 3：修正 playbook（如有发现）

原文核实后若发现 playbook 有错或漏：
- **直接 Edit playbook** 改对（用原文佐证补全）
- 不要在 design 文档里保留"修正/playbook 未提"的元叙述

### 步骤 4：写设计文档（按统一结构）

按下方【统一文档结构】写。一份一份写，写完一份更新 TodoWrite。

### 步骤 5：自审（每份提交前必做）

跑下方【自审脚本】，重点查：
1. 死链（raw 链接全部解析）
2. 残留对比语言（grep "playbook 未提/修正/补全/与 playbook"）
3. 数字无来源（每个数字都应有 📖 链接）
4. 附录接口完整性

### 步骤 6：跨文档链接检查

确认各份之间的相互引用（"详见 01a §二"、"前置：先看 02-shared"）路径正确。

### 步骤 7：提交（commit message 用下方【模板】）

## 文档拆分原则（固定，无需与用户确认）

### 总原则：以 playbook 配方为主，再纳入配方之外的有价值策略

**主线（必须做）**：playbook §三的每个配方（A/B/C/D...）→ 每个配方一份设计文档，按 playbook 的递进顺序排 Phase 1/2/3...

**附加（同步做）**：通读 playbook §二证据表、§七组合潜力、§九附录，把**有独立 alpha、有完整原文佐证、可独立运行**的机制也写成设计文档。这些机制虽然不在 §三配方里，但同样有价值，缺失会让落地设计不完整。

### 基本单位：一个"策略"= 一套完整交易系统

拆分单位不是 playbook 的"配方"概念，而是**可独立运行的完整策略**（数据→信号→选股/选行业→调仓→绩效→红线→升级路径）。

### 拆分维度

| 维度 | 示例 |
|---|---|
| **按复杂度递进** | A 入门验证 → B 主力 → C 控回撤 → D 正交叠加 |
| **按 alpha 路径** | 量价 / 基本面 / 资金流 / 宏观 / 情绪（不同数据源、不同逻辑）|
| **共享层单独成文** | 数据/工具/前视防护/下单层，避免重复 |

### 命名规范

```
0N-shared-<主题>-infrastructure.md   ← 共享层
0Na-<策略简述>.md                     ← Phase 1（配方 A）
0Nb-<策略简述>.md                     ← Phase 2（配方 B）
...
0Nx-<附加策略简述>.md                 ← playbook 之外的独立 alpha
0Ny-<附加策略简述>.md
0Nz-<附加策略简述>.md
```

### 附加机制的判断标准

§二/§七/§九的内容**符合以下任一**就写成设计文档：
- 有独立 alpha（绩效可对标，不是"辅助/增强"）
- 有完整原文佐证（因子构造/参数/绩效都查得到）
- 可独立运行（不依赖其他策略先跑通）
- 与主线配方正交（叠加有互补价值）

**不符合的**维持参考，不写成设计文档（如：纯宏观定性框架、辅助过滤层、单因子绩效过弱的）。

## 统一文档结构（每份设计文档必用）

```
# #0X 方向 · 策略名 — 详细实现

> **定位**：本文是 [playbook](../strategy-playbooks/0N-xxx.md) 配方X 的**策略详细实现**
>   ——介于 playbook 与代码之间的中间层。读完本文，任何人都能照着写出代码，
>   但本文不陷入代码细节。
> **角色**：在家族里的定位（入门/主力/控回撤/正交叠加/时机信号等）
> **来源**：📖 [机构 年.月《研报标题》](../../raw/articles/[时间戳]文件名.md)

---

## 一、策略定位
  1.1 赚什么钱（alpha 来源 + 一句话逻辑）
  1.2 在家族里的角色（与其他策略的关系表）
  1.3 不适合什么场景

## 二、信号逻辑（核心，用文字+公式，不写代码）
  - 因子定义（每个都要带原文佐证）
  - 关键参数的选择依据（为什么是这个值）
  - 算法完整流程（举一个具体例子走一遍）

## 三、选股/选行业规则
  - 每日/每月盘后例行流程
  - 硬过滤条件（带阈值表）
  - ⚠️ 前视偏差检查

## 四、调仓与持仓
  - 建仓时点（T+1 等）
  - 调仓频率与时点
  - 持仓方式（等权/数量）
  - 费用

## 五、参数表（每个参数：值 / 原文依据 / 敏感性 / 备注）

## 六、绩效预期与可信度
  - 原文绩效（带口径标注）
  - 个人投资者降级预期（打折 + 原因）

## 七、失效红线（表格：红线 / 表现 / 监控动作）

## 八、升级路径（ASCII 树状图：本策略 → 加路径 → 终极合成 → 附加）

## 附录 A：数据需求（字段级，不写接口名）
## 附录 B：数据接口（实现参考，非主体；akshare/QMT；缺口三档应对）
```

### 各 section 的写法要点

| section | 要点 | 避免 |
|---|---|---|
| 一、定位 | 一句话讲清赚什么钱；角色表对比其他策略 | 啰嗦铺陈 |
| 二、信号逻辑 | 公式 + 每步取什么值；每个关键决策带原文佐证；举具体例子 | 写函数签名/伪代码 |
| 三、选股规则 | 流程图（ASCII 或文字步骤）；阈值表 | — |
| 四、调仓 | 表格对比不同口径；标注原文依据 | — |
| 五、参数表 | **每行带原文链接**；标注敏感性 | 只给值不给依据 |
| 六、绩效 | **标注口径**（多头/多空/超额/胜率定义）；个人投资者打折预期 | 直接抄原文数字不打折 |
| 七、红线 | 表格；🔴硬线 vs 🟡软线 | 模糊表述 |
| 八、升级路径 | ASCII 树状图，清晰展示进阶关系 | — |
| 附录 A | 字段级（"需要单季归母净利"），不写接口名 | — |
| 附录 B | akshare/QMT 接口表；缺口标注三档应对 | 把接口名写进主体 |

## 格式规范

### 原文佐证标准写法（强制）

```markdown
> 📖 [机构 年.月《研报标题》](../../raw/articles/[时间戳]文件名.md) §章节："原文关键句（引号引用，≤2句，可拼接用……，不改原意）"
```

- **每个关键决策/参数/绩效都要有原文佐证**
- 机构名简写统一：开源金工 / 国君配置 / 中银量化 / 广发金工 / 东方证券 / 招商定量 / 华泰金工 / 华安金工 / 华创金工 / 东北金工 / 中金固收 / 中信建投 / 申万宏源

### 数据缺口三档应对（强制写法）

当某数据 akshare 无/不稳定时，写三档实现路径：

```markdown
> ⚠️ **三档实现路径**（数据源升级时切换）：
> - **档 1（推荐起步）**：日线代理版（具体替代方法）——✅ 立即可用，但是近似版
> - **档 2（数据升级后）**：L2/Tick 数据按原文方法——需 QMT L2 权限
> - **档 3（付费源）**：聚宽/米筐/Wind——需付费
```

### 绩效口径标注（强制）

每个绩效数字必须标注：
- **多头年化 / 多空年化 / 超额年化**（三选一或多个）
- **回测期**
- **胜率定义**（月度/年度/对冲）
- **是否计费用**（"原文绩效未计交易费用"）

### 个人投资者降级预期（强制）

不能直接抄原文数字，必须给打折预期：
```
原文的 X-Y 折（即年化 Z-W% 而非 V%）
主要折扣：未计费用/未计涨跌停/数据覆盖下降/数据时延/资金容量
```

## 易错点（实战踩过的坑）

1. **架构拆分自主决策，不询问用户**——按"以配方为主 + 纳入配方外有价值机制"的原则自己拆，不要用 AskUserQuestion 问"拆几份/是否纳入附加"。只在 playbook 结构不清或某机制是否有价值存在模糊时才问。

2. **不要仅凭 playbook 写设计文档**——playbook 是二手总结，因子构造常被简化、参数常只给一个值不给依据。**每份必须 Read 原文核实**。

3. **playbook 有错要直接改 playbook**——不要在 design 文档里保留"修正/playbook 未提"的元叙述。先改 playbook，再让 design 与修正后的 playbook 一致。

4. **引用必须带链接**——`📖 [机构 年.月](../../raw/articles/...)`，不能只写"华创 2018"不带链接。

5. **绩效数字必须核对口径**——多头超额 vs 多空、年化 vs 累计、胜率定义（月度/年度/对冲）。事实错误高发区。

6. **不能直接抄原文绩效**——必须给"个人投资者降级预期"（打折 + 原因）。

7. **缺数据不要降级或省略**——写"三档实现路径"，起步走档 1 但完整版接口预留。

8. **接口名进附录**——主体只写字段级需求（"需要单季归母净利"），不写"用 akshare 的 stock_profit_sheet_by_quarterly_em"。

10. **跨文档链接要正确**——"详见 01a §二"这种引用，路径要写对（同目录直接 `01a-xxx.md`）。

11. **不局限于 playbook 配方**——§二证据表、§七组合潜力、§九附录里有价值的独立机制也要写成设计文档（如 02f/02g/02h）。
